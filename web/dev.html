The two seams

Hai đường nối

These are why the codebase is testable. Learn these two and most of the rest follows.

Đây là lý do codebase test được. Hiểu hai cái này thì phần lớn còn lại tự sáng.

Server ↔ engine

Server ↔ engine

The HTTP layer depends on narrow interfaces, not the engine — split by side, so a test of the read path fakes nothing it doesn't use. Every route, SSE frame, write gate and 400 is covered by go test with a fake, needing no key and no database.

Tầng HTTP phụ thuộc vào các interface hẹp, không phải engine — chia theo từng bên, nên test đường đọc không phải fake thứ nó không dùng. Mọi route, frame SSE, cửa ghi và lỗi 400 đều test được bằng go test với fake, không cần key, không cần database.

type Answerer interface { // read Answer(ctx, Ask) (Reply, error) // Ask.Fresh skips the cache Corpus(limit int) (db.Corpus, error) } type Knowledge interface { // the BA ⇄ DEV loop Queue(limit int) (db.Queue, error) OpenTicket(question, miss string) (db.Ticket, error) Draft / Confirm / Reject // one transition each History(limit int) ([]db.Cached, error) } type Importer interface { // documents in, from the browser Import(ctx, dir string, files []File) (Result, error) }

Deps.Know and Deps.Docs are both optional: leave one nil and its routes simply aren't registered, so a read-only build has no write surface to secure rather than a half-wired one.

Deps.Know và Deps.Docs đều là tuỳ chọn: để nil thì route của nó không được đăng ký, nên bản chỉ-đọc không có chỗ ghi nào cần bảo vệ, thay vì có một nửa.

App ↔ transport

App ↔ transport

app.js never sees an AbortController, a TextDecoder or visualViewport. It states intent; the modules hide the mechanism.

app.js không bao giờ thấy AbortController, TextDecoder hay visualViewport. Nó chỉ nói ý định; các module giấu phần cơ chế.

const run = ask(q, { onToken, onCitations, onDone, fresh }); // chat.js run.stop(); // resolves, never throws await qa.act(id, "confirm", { answer }); // qa.js — throws WrongPass on 401/403 view.scrollToEnd(); // viewport.js

The two screens are two components. app.js is the shell — turns, health, corpus, the queue both screens list; ba.js owns what only BA mode touches (drafts, the unlock form, import progress). Three kinds of crossing, and no more: four props down, two events up (changed, ask), and toast injected because the pinned CDN URL lives in one file. In-DOM templates, so components still cost no build step — and every branch behind that contract lives in a composable, which is the section below.

Hai màn hình là hai component. app.js là lớp vỏ — lượt hỏi, health, corpus, hàng đợi mà cả hai màn hình đều hiển thị; ba.js giữ những gì chỉ chế độ BA dùng (bản nháp, form mở khoá, tiến trình import). Ba loại chỗ giao nhau, không hơn: bốn props xuống, hai event lên (changed, ask), và toast được inject vì URL CDN đã pin chỉ nằm ở một file. Template in-DOM, nên component vẫn không cần bước build — và mọi nhánh logic phía sau contract đó nằm trong composable, đúng mục bên dưới.

Test without a key

Test không cần key

internal/aitest serves a fake OpenAI-compatible provider over httptest, and the real client talks to it. That covers what a new provider actually breaks — request encoding, index-ordered embeddings, SSE parsing — which a hand-written fake client would not. It can also misbehave on purpose.

internal/aitest dựng một provider giả tương thích OpenAI qua httptest, và client thật nói chuyện với nó. Nó phủ đúng những chỗ provider mới hay làm vỡ — encode request, embeddings xếp theo index, parse SSE — thứ mà fake client viết tay bỏ sót. Nó còn có thể hỏng có chủ đích.

make checktests + gofmt + vet + staticcheck + deadcode + secret scanmake livethe real provider: both endpoints + embedding widthmake smokeend to end: ingest a fixture, ask, check it cites the file
Point make live at a new provider before ingesting anything real. It tells you in seconds whether /embeddings is missing, which is the one gap that stops indexing dead. Chạy make live với provider mới trước khi index thật. Nó cho biết trong vài giây là có thiếu /embeddings không — đúng cái lỗ làm index chết hẳn.

The knobs people actually turn

Những nút thật sự hay bị xoay

In rough order of how often, and what each one costs.

Xếp theo mức độ hay dùng, kèm giá phải trả.

1
Answer quality → how many sections reach the model Chất lượng trả lời → bao nhiêu đoạn tới được model

TOP_K in .env. Raise it when answers miss context that you know is indexed; lower it when they wander. Costs tokens per question, nothing else. No re-index.

TOP_K trong .env. Tăng khi câu trả lời thiếu ngữ cảnh mà bạn biết đã index; giảm khi nó lan lan. Chỉ tốn token mỗi câu hỏi, không gì khác. Không cần index lại.

2
Answer quality → how a document is cut into sections Chất lượng trả lời → cách tài liệu được cắt thành đoạn

minChars / maxChars in internal/rag/chunk.go. A section under minChars is merged with the ones next to it, and an oversized one is split by paragraph and then by line — a markdown table keeps its header row in every part. Measured on five specification documents: the old rule left 228 of 471 chunks under 300 characters and ten tables over the limit, the largest 11,651. Costs a re-ingest: existing rows keep the old cut until ./bin/ingest corpus runs again.

minChars / maxChars trong internal/rag/chunk.go. Đoạn nhỏ hơn minChars sẽ được gộp với các đoạn kế bên, đoạn quá lớn bị cắt theo paragraph rồi theo dòng — bảng markdown giữ lại dòng header ở mọi phần. Đo trên năm tài liệu đặc tả: luật cũ để lại 228/471 đoạn dưới 300 ký tự và mười cái bảng vượt hạn mức, lớn nhất 11.651. Phải ingest lại: dữ liệu đang có vẫn theo cách cắt cũ tới khi chạy lại ./bin/ingest corpus.

3
Grounding → the prompt Mức căn cứ → prompt

internal/rag. This is where "answer only from these sections, and say so when it isn't there" lives. Change it and re-run make smoke: it fails if the reply stops citing its file.

internal/rag. Chỗ chứa câu "chỉ trả lời từ các đoạn này, và nói rõ khi không có". Sửa rồi chạy lại make smoke: nó fail nếu câu trả lời không còn dẫn nguồn.

4
A different provider or model Đổi provider hoặc model

AI_BASE_URL / EMBED_BASE_URL and the model names. Chat and embeddings may live on different hosts — coding-agent gateways often serve chat only. When they are different vendors, set EMBED_API_KEY too: one key is not valid at two providers, so splitting the URL alone just fails auth.

AI_BASE_URL / EMBED_BASE_URL và tên model. Chat và embeddings có thể ở hai host khác nhau — gateway cho coding agent thường chỉ có chat. Nếu là hai nhà cung cấp khác nhau, set thêm EMBED_API_KEY: một key không dùng được ở hai provider, tách URL mà không tách key thì chỉ lỗi auth.

# chat stays where it is, embeddings go to OpenAI EMBED_BASE_URL=https://api.openai.com/v1 EMBED_API_KEY=sk-… EMBED_MODEL=text-embedding-3-small EMBED_DIM=1536
Changing the embedding model means a full re-index. Vectors from two models are not comparable. EMBED_DIM must match exactly; delete knowledge.db and ingest again. Đổi embedding model là phải index lại toàn bộ. Vector của hai model không so sánh được với nhau. EMBED_DIM phải khớp chính xác; xoá knowledge.db rồi ingest lại.
5
Who may write, and where their answers land Ai được ghi, và câu trả lời của họ đi đâu

BA_PASS gates the two actions that change what the engine says — confirm and dismiss. Empty means the instance has no write surface at all, which is the safe way to forget a secret. CORPUS_DIR is the folder ingest reads and where a confirmed answer is written as qa/ticket-N.md; it is why the database stays derived. Neither needs a re-index.

BA_PASS khoá hai hành động đổi câu trả lời của engine — confirm và dismiss. Để trống thì instance không có chỗ ghi nào, đó là cách an toàn khi quên đặt secret. CORPUS_DIR là thư mục ingest đọc và là nơi ghi câu trả lời đã confirm thành qa/ticket-N.md; nhờ vậy database vẫn chỉ là thứ dựng lại được. Cả hai đều không cần index lại.

BA_PASS=… # empty = read-only instance CORPUS_DIR=docs # ingest reads it; confirms write into it
The answer cache is keyed on the corpus, not a clock. A repeat question skips both provider calls. Any ingest — a document or a BA confirm — changes the corpus signature and drops the whole cache, so a cached answer can never outlive the sources it cites. There is no TTL to tune, and Ask.Fresh (Regenerate) bypasses it. Cache câu trả lời khoá theo corpus, không theo thời gian. Câu hỏi lặp lại bỏ qua cả hai lần gọi provider. Bất kỳ lần ingest nào — tài liệu hay một confirm của BA — đều đổi signature của corpus và xoá sạch cache, nên câu trả lời trong cache không bao giờ sống lâu hơn nguồn nó dẫn. Không có TTL nào để tinh chỉnh, và Ask.Fresh (Regenerate) thì bỏ qua cache.

Native ES modules, no build step — edit web/app/*.js and reload. It is embedded in the binary, so make build before you test the built artifact, or you will debug the old bytes.

ES module thuần, không có bước build — sửa web/app/*.js rồi reload. Nó nằm trong binary, nên phải make build trước khi test bản đã build, không thì bạn đang debug bytes cũ.

How a scoped answer stays honest

Câu trả lời có scope giữ đúng bằng cách nào

A scope is a promise — answer from this folder — and there are exactly two ways to break it. Both are covered by a test, because both fail as a confident answer rather than an error.

Scope là một lời hứa — trả lời từ thư mục này — và có đúng hai cách làm nó sai. Cả hai đều có test, vì cả hai đều lỗi dưới dạng một câu trả lời nghe rất chắc chứ không phải một error.

1
Filter before ranking, never after Lọc trước khi xếp hạng, không phải sau

Both retrievers take the scope as a pre-filter — the vector KNN via a chunk_id IN (…) constraint, BM25 via the same subquery on rowid — so k counts matches inside the folder. Filtering the fused result instead would return fewer than TOP_K sections and quietly thin the answer. sqlite-vec honours that constraint as of v0.1.6; TestScopedSearchRanksWithinTheScope stacks twenty nearer out-of-scope chunks against five far ones to prove it still does.

Cả hai bộ truy xuất nhận scope như một pre-filter — vector KNN qua điều kiện chunk_id IN (…), BM25 qua đúng subquery đó trên rowid — nên k đếm các kết quả trong thư mục. Nếu lọc sau khi fuse thì sẽ trả về ít hơn TOP_K đoạn và làm câu trả lời mỏng đi âm thầm. sqlite-vec tôn trọng điều kiện đó từ v0.1.6; TestScopedSearchRanksWithinTheScope dựng hai mươi đoạn ngoài scope gần hơn đối đầu năm đoạn xa để chứng minh nó vẫn vậy.

2
The scope is part of the cache key, not the signature Scope thuộc về cache key, không thuộc signature

The same words asked in another folder are another question, so the key is scope + question. It is deliberately not in corpus_sig: a signature is pruned when it changes, so scoping it would empty every other folder's cache on each pick. A scope is canonicalised in exactly one place — rag.Scope — because two spellings of one folder are two cache entries and one of them is always paid for twice.

Cùng câu chữ mà hỏi ở thư mục khác là câu hỏi khác, nên key là scope + câu hỏi. Nó cố tình không nằm trong corpus_sig: signature bị xoá khi thay đổi, nên nếu đưa scope vào đó thì mỗi lần chọn thư mục sẽ xoá cache của mọi thư mục khác. Scope được chuẩn hoá ở đúng một chỗ — rag.Scope — vì hai cách viết của một thư mục là hai entry cache, và một trong hai luôn bị trả tiền lần nữa.

The picker lives in the dock, not on the empty screen: narrowing is needed after an answer at least as often as before one, and a control that disappears with the empty state can only be reached by clearing the thread. One instance serves both, because the dock is always there in ASK mode.

Bộ chọn nằm trong dock, không nằm ở màn hình trống: nhu cầu thu hẹp xuất hiện sau một câu trả lời không ít hơn trước đó, và một control mất đi cùng màn hình trống thì chỉ còn cách xoá cả mạch hội thoại mới tới được. Một chỗ phục vụ cả hai, vì dock luôn có mặt ở chế độ ASK.

The tree itself is the library's <nes-tree>, built from GET /api/corpus paths in web/app/tree.js — no API was added for it. The element renders once from a child JSON payload, which is why the component replaces it instead of mutating it.

Cây thư mục là <nes-tree> của thư viện, dựng từ đường dẫn của GET /api/corpus trong web/app/tree.js — không thêm API nào. Element chỉ render một lần từ payload JSON con, nên component thay nó chứ không sửa nó.

Diagrams are detected by content, not by the fence label. A model asked for ```mermaid writes a bare ``` often enough that labelling was never a usable signal — the reported case was a fence whose first line was graph TD;, rendered as source code. web/app/diagram.js matches the diagram kinds on a block's first line instead, and one predicate serves both callers (whether to fetch the 3.4 MB renderer, and which block to replace) so they cannot disagree. The renderer is lazy and integrity-checked; if it never arrives the fence stays, which reads. In the answer the drawing is fitted so its shape is visible, and a tap opens a copy at the size in its viewBox — pinned in JS because an SVG with a viewBox has no intrinsic width for CSS to use. The copy gets its own id and its mermaid stylesheet rewritten to match, or it renders as black boxes. Sơ đồ được nhận theo nội dung, không theo nhãn của fence. Model được yêu cầu ghi ```mermaid nhưng rất hay ghi ``` trơn — case được báo là fence trơn với dòng đầu graph TD;, hiện ra thành code. web/app/diagram.js đối chiếu các loại sơ đồ ở dòng đầu của block, và một hàm phán đoán duy nhất dùng cho cả hai chỗ (có tải renderer 3.4 MB không, và thay block nào) để chúng không lệch nhau. Renderer tải lười và có kiểm tra integrity; nếu không tải được thì vẫn là fence, vẫn đọc được. Trong câu trả lời sơ đồ được thu để thấy tổng thể, bấm vào là mở bản copy đúng kích thước trong viewBox — set bằng JS vì SVG có viewBox không có chiều rộng nội tại cho CSS dùng. Bản copy được đổi id và sửa lại stylesheet mermaid theo id mới, không thì nó vẽ ra toàn khối đen.

Filing a gap a BA can answer

Báo gap sao cho BA trả lời được

Your side of the QA loop. Three things before you file, so the BA gets a real gap and not a rephrasing problem.

Phần việc của bạn trong vòng QA. Ba việc trước khi báo, để BA nhận đúng một gap thật chứ không phải chuyện diễn đạt.

1
Ask once more in the document's words Hỏi lại một lần bằng đúng từ trong tài liệu

Half of retrieval is keyword matching, so the identifier, error code or config key beats a paraphrase. Regenerate also skips the answer cache, which is what you want if you suspect a stale answer.

Một nửa của truy xuất là khớp từ khoá, nên tên identifier, mã lỗi hay key config ăn hơn diễn giải lại. Regenerate cũng bỏ qua cache, đúng thứ bạn cần khi nghi câu trả lời cũ.

2
Check the corpus list Xem danh sách corpus

“Retrieval missed it” and “the document was never indexed” read identically from a chat reply. The indexed-sources list on the empty screen — or GET /api/corpus — is the only thing that tells them apart, and the second one is not a ticket, it is a missing file.

“Truy xuất trượt” và “tài liệu chưa từng được index” đọc từ câu trả lời thì y như nhau. Danh sách nguồn đã index ở màn hình trống — hoặc GET /api/corpus — là thứ duy nhất phân biệt được, và trường hợp thứ hai không phải ticket, mà là thiếu file.

3
Then Ask BA — don't retype the question Rồi bấm Ask BA — đừng gõ lại câu hỏi

The button sends the question and the answer that failed, so the BA can see whether the documents are wrong or merely silent. Filing the same gap twice is harmless: identical questions fold into one ticket, so you get the existing one back rather than adding to the queue.

Nút đó gửi cả câu hỏi và câu trả lời sai, để BA thấy tài liệu sai hay chỉ đang thiếu. Báo trùng cũng không sao: câu hỏi giống nhau gộp vào một ticket, nên bạn nhận lại ticket cũ chứ không làm dài hàng đợi.

The turn keeps a badge showing that ticket's real state. When it reaches IN KNOWLEDGE the answer is a document: ask again and you get it with a citation to qa/ticket-N.md, and free from the cache after that.

Lượt hỏi đó giữ một nhãn hiện trạng thái thật của ticket. Khi nó tới IN KNOWLEDGE thì câu trả lời đã là tài liệu: hỏi lại sẽ nhận được kèm dẫn nguồn tới qa/ticket-N.md, và sau đó miễn phí từ cache.

Holding BA_PASS doesn't make it your ticket. Confirming writes into the corpus for the whole team. If you know the answer but not that it is the answer, leave it for someone who owns the subject — the four states and the guidance for answering well are on the BA page. Có BA_PASS không có nghĩa ticket đó là của bạn. Confirm là ghi vào corpus cho cả team. Nếu bạn biết câu trả lời nhưng không chắc đó là câu trả lời đúng thẩm quyền, để người nắm nghiệp vụ làm — bốn trạng thái và cách viết câu trả lời tốt nằm ở trang BA.

Four rules, four tests

Bốn quy tắc, bốn test

All four break silently — nothing fails to build, and the browser looks fine until the exact moment someone uses the feature. So they are checked in Go, in web/frontend_test.go, and each was mutation-tested against an injected violation.

Cả bốn đều sai một cách im lặng — không có gì build lỗi, và browser trông vẫn ổn tới đúng lúc có người dùng tính năng đó. Nên chúng được kiểm bằng Go, trong web/frontend_test.go, và mỗi cái đều đã được mutation-test bằng một lỗi tiêm vào.

TestPlumbingDoesNotImportVue
A ref in session.js and that file can only run inside a mounted app.
Một ref lọt vào session.js là file đó chỉ chạy được trong app đã mount.
TestComposablesDoNotImportEachOther
What a composable needs arrives as an argument — reactive inputs it does not own as getters, or it freezes on the array that existed at setup.
Thứ một composable cần thì được truyền vào — input reactive nó không sở hữu thì truyền dạng getter, không thì nó đóng băng vào array lúc setup.
TestComponentsHoldNoLogic
This is the drift that grew ba.js to 179 lines holding the password gate, the import pipeline and the ticket transitions at once.
Đây đúng là kiểu trôi đã làm ba.js phình lên 179 dòng chứa cả gate mật khẩu, đường import và các chuyển trạng thái ticket.
TestTemplatesBindNothingUndefined
A missing key in a setup() return is undefined at render, with no error and no warning — just a blank where a badge should be.
Thiếu một key trong setup() return là undefined lúc render, không error không warning — chỉ là chỗ trống nơi đáng ra có badge.
No JavaScript linter in the gate, on purpose. Measured: @antfu/eslint-config pulls 255 packages and 113 MB to report three small findings here, and its best rules — eslint-plugin-vue's reactivity-loss checks — do not fire without SFCs. It is wired as make lint-js, installed into .cache/, with nothing committed for it. Promote it the day TypeScript or .vue files land. Không có linter JavaScript trong gate, và đó là chủ ý. Đã đo: @antfu/eslint-config kéo về 255 package và 113 MB để báo ba finding nhỏ ở đây, còn các rule mạnh nhất của nó — reactivity-loss của eslint-plugin-vue — không chạy khi không có SFC. Nó được wire thành make lint-js, cài vào .cache/, không commit gì cho nó. Đẩy nó vào gate vào ngày TypeScript hoặc file .vue xuất hiện.

These pages are the spec

Chính các trang này là spec

Not a description of the code — the input to it. A section that maps to code declares that mapping in its own markup, and make check fails while the mapping is wrong in either direction.

Không phải bản mô tả code — mà là đầu vào của code. Mục nào ứng với code thì khai báo luôn trong markup của nó, và make check sẽ đỏ khi mối nối đó sai ở bất kỳ chiều nào.

The five steps, in order

Năm bước, theo thứ tự

1
Write the section first Viết mục tài liệu trước

On the page for its audience: Guide for everyone, ba.html for a BA, this page for a DEV, deploy.html for whoever hosts it. Both languages, inline — the toggle is CSS-only, so a missing half is a visible gap rather than a silent one.

Trên trang đúng đối tượng: Hướng dẫn cho mọi người, ba.html cho BA, trang này cho DEV, deploy.html cho người host. Viết cả hai ngôn ngữ ngay tại chỗ — toggle chỉ là CSS, nên thiếu một nửa sẽ thấy ngay chứ không im lặng.

2
Declare the join on the <section> Khai báo mối nối trên <section>
<section id="scope" data-feature="scope" data-api="POST /api/chat" data-env="TOP_K" data-test="TestScopedSearchRanksWithinTheScope">

data-feature is a stable id — how a change is addressed in a conversation or a ticket. The other three are lists: routes, environment variables, and the tests that fail when the feature breaks.

data-feature là id ổn định — cách gọi tên một thay đổi khi trao đổi hay khi mở ticket. Ba cái còn lại là danh sách: route, biến môi trường, và các test sẽ đỏ khi tính năng bị hỏng.

3
Run make check and read the red Chạy make check và đọc chỗ đỏ

It fails while a name you declared does not exist yet — so the test name in the markup is the test you write next. That is the whole mechanism: the spec is red until the code agrees with it.

Nó đỏ khi một cái tên bạn khai báo còn chưa tồn tại — nên tên test trong markup chính là test bạn viết tiếp. Cơ chế chỉ có thế: spec còn đỏ thì code còn chưa khớp.

4
Implement until it is green Làm cho tới khi xanh

The documentation needs no second pass: it was the input, so it is already correct when the build goes green. This is the step an agent harness can take on its own — the spec says what to build and what must pass.

Tài liệu không cần sửa lại lần nữa: nó là đầu vào, nên khi build xanh là nó đã đúng. Đây là bước một AI agent có thể tự làm — spec đã nói rõ làm gì và phải xanh ở đâu.

5
Nothing to publish by hand Không phải publish gì bằng tay

spec.json and llms.txt are regenerated from the pages by cmd/rendocs on every push to main, next to the pages themselves. There is no second copy to update, which is why there is no second copy to forget.

spec.json và llms.txt được sinh lại từ các trang bởi cmd/rendocs mỗi lần push lên main, nằm ngay cạnh các trang. Không có bản copy thứ hai để cập nhật, nên cũng không có bản thứ hai để quên.
