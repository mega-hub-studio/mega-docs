How it works

Cách hoạt động

<%diagram "howitworks"%>

You point make ingest at a folder. Every .md / .txt file is read once — nothing leaves the machine except the text sent for embedding.

Bạn trỏ make ingest vào một thư mục. Mỗi file .md / .txt được đọc một lần — không gì ra khỏi máy ngoài đoạn text gửi đi embed.

Each file is split into sections, each section becomes a vector, and both land in one SQLite file. That file is the whole database — and it is rebuilt from the folder above, so the folder is what you back up.

Mỗi file được cắt thành đoạn, mỗi đoạn thành một vector, và cả hai nằm trong một file SQLite. File đó là toàn bộ database — và nó dựng lại được từ thư mục ở trên, nên thứ cần backup là thư mục đó.

Your question runs as both a meaning search and a keyword search (BM25), and the two rankings are fused. Keyword is what finds error codes, config keys and function names that pure semantic search walks straight past.

Câu hỏi của bạn chạy đồng thời tìm theo ngữ nghĩa và tìm theo từ khoá (BM25), rồi hợp nhất hai bảng xếp hạng. Từ khoá là thứ bắt được mã lỗi, tên config, tên hàm — những cái tìm theo ngữ nghĩa thuần bỏ sót.

Only the best few sections move on. This is the step that decides quality: if the answer is wrong, it is usually because the right section never got here.

Chỉ vài đoạn tốt nhất đi tiếp. Đây là bước quyết định chất lượng: nếu câu trả lời sai, thường là vì đoạn đúng không tới được đây.

The model is told to answer only from those sections, and to say so when the answer isn't in them. It streams back word by word, and every [1] is a link down to the file it came from.

Model bị buộc chỉ trả lời từ các đoạn đó, và phải nói rõ khi không có thông tin. Nó stream về từng chữ, và mỗi [1] là link nhảy xuống đúng file đã dùng.

Reading is open; publishing is not. Anyone can ask, see the queue, and file a gap — a DEV who can't report one stops reporting them. Confirming and dismissing need the BA password (BA_PASS), because those two change what the engine will tell everyone else. If no password is set, the instance has no write surface at all and BA mode says so. Đọc thì mở; publish thì không. Ai cũng hỏi được, xem được hàng đợi, và báo được phần thiếu — DEV mà không báo được thì sẽ thôi không báo nữa. Confirm và dismiss cần mật khẩu BA (BA_PASS), vì hai việc đó đổi câu trả lời cho tất cả mọi người. Nếu chưa đặt mật khẩu, instance không có chỗ ghi nào cả và chế độ BA sẽ nói rõ điều đó.
Why a confirm writes a file. A confirmed answer lands in docs/qa/ticket-N.md, not just in the database — so it is reviewable in a diff, it goes in git with the rest of the documents, and re-indexing from scratch reproduces it. The database stays disposable. Vì sao confirm lại ghi ra file. Câu trả lời đã confirm nằm ở docs/qa/ticket-N.md, chứ không chỉ trong database — nên xem được trong diff, đi vào git cùng các tài liệu khác, và index lại từ đầu vẫn dựng đúng như vậy. Database vẫn là thứ có thể bỏ đi.

Nếu đăng nhập bị từ chối, email của bạn nằm ngoài policy — người host phải mở thêm, bạn thử lại cũng không được.

Nothing to install, but you have to be on the office network — from home it simply will not load. The browser will ask for a username and password; both come from the host.

Không phải cài gì, nhưng bạn phải ở trong mạng công ty — từ nhà thì đơn giản là không mở được. Browser sẽ hỏi username và mật khẩu; cả hai lấy từ người host.

Save it in the keychain, not in a chat message. It is one password shared by everyone who reads, so it should live in your browser's password manager and nowhere else. Lưu vào keychain, đừng gửi qua chat. Đây là một mật khẩu dùng chung cho tất cả người đọc, nên để trong password manager của browser, không để chỗ nào khác.

When something's wrong

Khi có vấn đề

The four failures that actually happen, and what each one means.

Bốn lỗi thực sự hay xảy ra, và mỗi lỗi nghĩa là gì.

"Nothing is indexed yet" The app is fine, the index is empty — run make ingest DOCS=./docs. This message exists so an empty index can't be mistaken for a broken search. "Nothing is indexed yet" App bình thường, index đang trống — chạy make ingest DOCS=./docs. Thông báo này có để index trống không bị hiểu lầm thành tìm kiếm hỏng.
Ingest says "no embeddings endpoint" Your chat provider doesn't serve /embeddings — common for coding-agent gateways. Point embeddings elsewhere and keep chat where it is. Two ways: a local Ollama (free), or OpenAI for embeddings only. If the two are different vendors, EMBED_API_KEY is required — one key is not valid at both. Ingest báo "no embeddings endpoint" Provider chat của bạn không có /embeddings — rất thường gặp ở các gateway kiểu coding-agent. Trỏ embeddings sang chỗ khác và giữ chat ở nguyên đó. Hai cách: Ollama local (miễn phí), hoặc dùng OpenAI chỉ cho embeddings. Nếu là hai nhà cung cấp khác nhau thì phải set EMBED_API_KEY — một key không dùng được ở cả hai.
# free, nothing leaves the machine EMBED_BASE_URL=http://localhost:11434/v1 EMBED_MODEL=nomic-embed-text EMBED_DIM=768 # or OpenAI for embeddings only EMBED_BASE_URL=https://api.openai.com/v1 EMBED_API_KEY=sk-… EMBED_MODEL=text-embedding-3-small EMBED_DIM=1536
The dot in the header is red The browser can't reach /api/health: the server is down, or the tunnel is. The conversation on screen is kept in the browser, so nothing is lost. Đèn trên header màu đỏ Browser không tới được /api/health: server chết, hoặc tunnel chết. Hội thoại đang hiển thị được lưu trong browser nên không mất gì.
