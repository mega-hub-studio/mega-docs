◈ Ask your own docs

◈ Tra cứu tài liệu nội bộ

A self-hosted question box over your team's documents. Answers are built only from what you indexed, and every claim links back to the file it came from. One Go binary, one SQLite file — no Docker, no Node, no vector database.

Hộp hỏi–đáp self-host trên tài liệu của team. Câu trả lời chỉ dựng từ những gì bạn đã index, và mỗi khẳng định đều dẫn ngược về đúng file gốc. Một binary Go, một file SQLite — không Docker, không Node, không vector database.

How it works

Cách hoạt động

<%diagram "howitworks"%>

You point make ingest at a folder. Every .md / .txt file is read once — nothing leaves the machine except the text sent for embedding.

Bạn trỏ make ingest vào một thư mục. Mỗi file .md / .txt được đọc một lần — không gì ra khỏi máy ngoài đoạn text gửi đi embed.

Each file is split into sections, each section becomes a vector, and both land in one SQLite file. That file is the whole database — back it up by copying it.

Mỗi file được cắt thành đoạn, mỗi đoạn thành một vector, và cả hai nằm trong một file SQLite. File đó là toàn bộ database — backup bằng cách copy nó.

Your question runs as both a meaning search and a keyword search (BM25), and the two rankings are fused. Keyword is what finds error codes, config keys and function names that pure semantic search walks straight past.

Câu hỏi của bạn chạy đồng thời tìm theo ngữ nghĩa và tìm theo từ khoá (BM25), rồi hợp nhất hai bảng xếp hạng. Từ khoá là thứ bắt được mã lỗi, tên config, tên hàm — những cái tìm theo ngữ nghĩa thuần bỏ sót.

Only the best few sections move on. This is the step that decides quality: if the answer is wrong, it is usually because the right section never got here.

Chỉ vài đoạn tốt nhất đi tiếp. Đây là bước quyết định chất lượng: nếu câu trả lời sai, thường là vì đoạn đúng không tới được đây.

The model is told to answer only from those sections, and to say so when the answer isn't in them. It streams back word by word, and every [1] is a link down to the file it came from.

Model bị buộc chỉ trả lời từ các đoạn đó, và phải nói rõ khi không có thông tin. Nó stream về từng chữ, và mỗi [1] là link nhảy xuống đúng file đã dùng.

Quick start

Bắt đầu nhanh

Three commands, on the machine that will hold the index.

Ba lệnh, trên máy sẽ giữ index.

1
Configure the AI provider Cấu hình AI provider
cp .env.example .env# fill in AI_API_KEY, AI_BASE_URL, modelsmake live✓ checks both endpoints + embedding width

make live answers the question that actually bites: does this provider have /embeddings? Without it, indexing cannot run.

make live trả lời đúng câu hỏi hay gây đau: provider này có /embeddings không? Thiếu nó là không index được.

2
Index your documents Index tài liệu
make ingest DOCS=./docsindexed docs/retrieval.md (12 chunks) done: 8/8 files, 74 chunks

Only .md / .txt. For PDF or DOCX, convert first — markitdown spec.pdf > docs/spec.md. Re-running on the same path updates it in place.

Chỉ nhận .md / .txt. PDF hay DOCX thì chuyển trước — markitdown spec.pdf > docs/spec.md. Chạy lại trên cùng đường dẫn thì cập nhật tại chỗ.

3
Start it Chạy
make build && ./bin/knowledgeKnowledge Engine on http://127.0.0.1:8080

The UI is compiled into the binary, so there is nothing else to deploy. Verify the whole chain any time with make smoke: it indexes a fixture, asks a question only that file can answer, and checks the reply cites it.

UI được biên dịch vào trong binary, nên không có gì khác phải deploy. Kiểm tra toàn bộ chuỗi bất cứ lúc nào bằng make smoke: nó index một file mẫu, hỏi câu chỉ file đó trả lời được, rồi kiểm tra câu trả lời có dẫn nguồn đúng file.

When something's wrong

Khi có vấn đề

The four failures that actually happen, and what each one means.

Bốn lỗi thực sự hay xảy ra, và mỗi lỗi nghĩa là gì.

"Nothing is indexed yet" The app is fine, the index is empty — run make ingest DOCS=./docs. This message exists so an empty index can't be mistaken for a broken search. "Nothing is indexed yet" App bình thường, index đang trống — chạy make ingest DOCS=./docs. Thông báo này có để index trống không bị hiểu lầm thành tìm kiếm hỏng.
Ingest says "no embeddings endpoint" Your chat provider doesn't serve /embeddings — common for coding-agent gateways. Point embeddings elsewhere and keep chat where it is: EMBED_BASE_URL=http://localhost:11434/v1 with EMBED_MODEL=nomic-embed-text and EMBED_DIM=768 (a local Ollama, free). Ingest báo "no embeddings endpoint" Provider chat của bạn không có /embeddings — rất thường gặp ở các gateway kiểu coding-agent. Trỏ embeddings sang chỗ khác và giữ chat ở nguyên đó: EMBED_BASE_URL=http://localhost:11434/v1 với EMBED_MODEL=nomic-embed-text và EMBED_DIM=768 (Ollama local, miễn phí).
The dot in the header is red The browser can't reach /api/health: the server is down, or the tunnel is. The conversation on screen is kept in the browser, so nothing is lost. Đèn trên header màu đỏ Browser không tới được /api/health: server chết, hoặc tunnel chết. Hội thoại đang hiển thị được lưu trong browser nên không mất gì.
Answers arrive all at once, not word by word Something between you and the app is buffering the stream — usually a proxy. make live reports whether the provider itself streams incrementally, which tells you which side to look at. Câu trả lời hiện một lần chứ không từng chữ Có gì đó giữa bạn và app đang buffer stream — thường là proxy. make live cho biết provider có stream từng phần hay không, để bạn biết cần xem phía nào.

Running it for the team — Tailscale, Cloudflare Tunnel, LAN, systemd, backups — is the next page.

Phần chạy cho cả team — Tailscale, Cloudflare Tunnel, LAN, systemd, backup — là trang tiếp theo.
