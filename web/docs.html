How it works

Cách hoạt động

<%diagram "howitworks"%>

You point make ingest at a folder. Every .md / .txt file is read once — nothing leaves the machine except the text sent for embedding.

Bạn trỏ make ingest vào một thư mục. Mỗi file .md / .txt được đọc một lần — không gì ra khỏi máy ngoài đoạn text gửi đi embed.

Each file is split into sections, each section becomes a vector, and both land in one SQLite file. That file is the whole database — and it is rebuilt from the folder above, so the folder is what you back up.

Mỗi file được cắt thành đoạn, mỗi đoạn thành một vector, và cả hai nằm trong một file SQLite. File đó là toàn bộ database — và nó dựng lại được từ thư mục ở trên, nên thứ cần backup là thư mục đó.

Your question runs as both a meaning search and a keyword search (BM25), and the two rankings are fused. Keyword is what finds error codes, config keys and function names that pure semantic search walks straight past.

Câu hỏi của bạn chạy đồng thời tìm theo ngữ nghĩa và tìm theo từ khoá (BM25), rồi hợp nhất hai bảng xếp hạng. Từ khoá là thứ bắt được mã lỗi, tên config, tên hàm — những cái tìm theo ngữ nghĩa thuần bỏ sót.

Only the best few sections move on. This is the step that decides quality: if the answer is wrong, it is usually because the right section never got here.

Chỉ vài đoạn tốt nhất đi tiếp. Đây là bước quyết định chất lượng: nếu câu trả lời sai, thường là vì đoạn đúng không tới được đây.

The model is told to answer only from those sections, and to say so when the answer isn't in them. It streams back word by word, and every [1] is a link down to the file it came from.

Model bị buộc chỉ trả lời từ các đoạn đó, và phải nói rõ khi không có thông tin. Nó stream về từng chữ, và mỗi [1] là link nhảy xuống đúng file đã dùng.

Getting in, the first time

Vào app lần đầu

The app is a web page on your team's own network. There is nothing to install for it and no account to create — but the address is not public, so getting in starts with one question to whoever hosts it.

App là một trang web nằm trong mạng nội bộ của team. Không phải cài gì cho nó và không phải tạo tài khoản — nhưng địa chỉ không công khai, nên việc đầu tiên là hỏi người host một câu.

The door your team chose

Cửa mà team bạn chọn

One install, once. Then the address works from anywhere — mobile data, home, a hotel — with no VPN to switch on and off by hand.

Cài một lần duy nhất. Sau đó địa chỉ dùng được từ bất cứ đâu — 4G, ở nhà, khách sạn — không phải bật/tắt VPN bằng tay.

  1. Ask the host to invite you to the company tailnet — you will get an email
  2. Nhờ người host mời bạn vào tailnet công ty — bạn sẽ nhận email
  3. Install the Tailscale app (App Store · Play Store · desktop) and sign in with the company account
  4. Cài app Tailscale (App Store · Play Store · desktop) rồi đăng nhập bằng tài khoản công ty
  5. Leave it connected — the toggle stays on; that is the whole maintenance
  6. Để nó kết nối — bật sẵn là xong, không phải làm gì thêm

No password prompt on the app itself: the tailnet already knows who you are, which is why this is the recommended door.

App sẽ không hỏi mật khẩu: tailnet đã biết bạn là ai, đó là lý do đây là cửa được khuyến nghị.

Nothing to install. Open the address and the browser asks you to sign in with Google or Microsoft first; after that it behaves like any internal site.

If the sign-in refuses you, your email is outside the policy — that is for the host to widen, not something you can retry around.

Nếu đăng nhập bị từ chối, email của bạn nằm ngoài policy — người host phải mở thêm, bạn thử lại cũng không được.

Nothing to install, but you have to be on the office network — from home it simply will not load. The browser will ask for a username and password; both come from the host.

Không phải cài gì, nhưng bạn phải ở trong mạng công ty — từ nhà thì đơn giản là không mở được. Browser sẽ hỏi username và mật khẩu; cả hai lấy từ người host.

Save it in the keychain, not in a chat message. It is one password shared by everyone who reads, so it should live in your browser's password manager and nowhere else. Lưu vào keychain, đừng gửi qua chat. Đây là một mật khẩu dùng chung cho tất cả người đọc, nên để trong password manager của browser, không để chỗ nào khác.

Quick start

Bắt đầu nhanh

Three commands, on the machine that will hold the index — for whoever runs it. If someone else runs it for your team, you want Getting in above instead.

Ba lệnh, trên máy sẽ giữ index — dành cho người chạy hệ thống. Nếu team bạn có người khác chạy, hãy xem Vào app lần đầu ở trên.

1
Configure the AI provider Cấu hình AI provider
cp .env.example .env# fill in AI_API_KEY, AI_BASE_URL, modelsmake live✓ checks both endpoints + embedding width

make live answers the question that actually bites: does this provider have /embeddings? Without it, indexing cannot run.

make live trả lời đúng câu hỏi hay gây đau: provider này có /embeddings không? Thiếu nó là không index được.

2
Index your documents Index tài liệu
make ingest DOCS=./docsindexed docs/retrieval.md (12 chunks) done: 8/8 files, 74 chunks

Only .md / .txt. For PDF or DOCX, convert first — markitdown spec.pdf > docs/spec.md. Re-running on the same path updates it in place.

Chỉ nhận .md / .txt. PDF hay DOCX thì chuyển trước — markitdown spec.pdf > docs/spec.md. Chạy lại trên cùng đường dẫn thì cập nhật tại chỗ.

3
Start it Chạy
make build && ./bin/knowledgemega-docs on http://127.0.0.1:8080

The UI is compiled into the binary, so there is nothing else to deploy. Verify the whole chain any time with make smoke: it indexes a fixture, asks a question only that file can answer, and checks the reply cites it.

UI được biên dịch vào trong binary, nên không có gì khác phải deploy. Kiểm tra toàn bộ chuỗi bất cứ lúc nào bằng make smoke: nó index một file mẫu, hỏi câu chỉ file đó trả lời được, rồi kiểm tra câu trả lời có dẫn nguồn đúng file.

When the answer isn't there

Khi câu trả lời chưa có

Điều hữu ích nhất của hệ thống này là biến câu hỏi nó chưa trả lời được thành câu nó trả lời được. DEV báo phần thiếu; BA trả lời; câu trả lời trở thành tài liệu. Không ai phải rời app, không ai sửa file bằng tay.

Reading is open; publishing is not. Anyone can ask, see the queue, and file a gap — a DEV who can't report one stops reporting them. Confirming and dismissing need the BA password (BA_PASS), because those two change what the engine will tell everyone else. If no password is set, the instance has no write surface at all and BA mode says so. Đọc thì mở; publish thì không. Ai cũng hỏi được, xem được hàng đợi, và báo được phần thiếu — DEV mà không báo được thì sẽ thôi không báo nữa. Confirm và dismiss cần mật khẩu BA (BA_PASS), vì hai việc đó đổi câu trả lời cho tất cả mọi người. Nếu chưa đặt mật khẩu, instance không có chỗ ghi nào cả và chế độ BA sẽ nói rõ điều đó.
Why a confirm writes a file. A confirmed answer lands in docs/qa/ticket-N.md, not just in the database — so it is reviewable in a diff, it goes in git with the rest of the documents, and re-indexing from scratch reproduces it. The database stays disposable. Vì sao confirm lại ghi ra file. Câu trả lời đã confirm nằm ở docs/qa/ticket-N.md, chứ không chỉ trong database — nên xem được trong diff, đi vào git cùng các tài liệu khác, và index lại từ đầu vẫn dựng đúng như vậy. Database vẫn là thứ có thể bỏ đi.

Using it well

Dùng cho hiệu quả

You never need a command for any of this. Four habits cover almost every question worth asking.

Phần này không cần lệnh nào. Bốn thói quen là đủ cho gần hết những câu đáng hỏi.

1 · Ask with the words the document uses

1 · Hỏi bằng đúng từ trong tài liệu

Search is half keyword, so an exact term — an error code, a config key, a screen name — is the strongest thing you can give it. Add the term and the question.

Tìm kiếm có một nửa là từ khoá, nên một thuật ngữ chính xác — mã lỗi, tên config, tên màn hình — là thứ mạnh nhất bạn có thể đưa vào. Ghi cả thuật ngữ và câu hỏi.

Instead ofAsk

“nói về hoàn tiền đi”“ai duyệt hoàn tiền trên 5tr, trong bao lâu?”

“cái này có tài liệu chưa?”“tài liệu nào định nghĩa SLA cho ticket tier-2?”

2 · Read the citation, not just the answer

2 · Đọc phần dẫn nguồn, đừng chỉ đọc câu trả lời

Every [1] is a link to the file the sentence came from. Opening one is the whole quality check: if the cited section really says it, the answer is as good as your document. If nothing is cited, treat it as a lead, not a fact.

Mỗi [1] là link tới file mà câu đó lấy ra. Mở nó chính là toàn bộ việc kiểm tra chất lượng: nếu đoạn được dẫn đúng là có nói vậy, câu trả lời tốt bằng tài liệu của bạn. Nếu không có dẫn nguồn nào, coi đó là gợi ý, chưa phải sự thật.

Three answers to distrust. No citation at all · a citation to a file you know is out of date · a confident answer to something your team only ever discussed in chat. The engine can only ever be as current as what was indexed. Ba loại câu trả lời nên nghi ngờ. Không có dẫn nguồn nào · dẫn tới file mà bạn biết đã cũ · trả lời chắc chắn về thứ mà team chỉ từng bàn trong chat. Hệ thống chỉ mới được bằng đúng những gì đã index.

3 · Check the index, then narrow it

3 · Kiểm tra thật sự đang có gì trong index — và thu hẹp lại

Browse documents is the folder tree of everything indexed, with each file's section count. Look there first when an answer feels thin — “not in the documents” and “the document was never added” look identical from the outside, and only that tree tells them apart.

Browse documents là cây thư mục của mọi thứ đã index, kèm số đoạn của từng file. Nhìn vào đó trước khi thấy câu trả lời mỏng — “không có trong tài liệu” và “tài liệu chưa từng được thêm” nhìn từ ngoài y như nhau, chỉ cây đó phân biệt được.

Tapping a folder there does the second job: the next answer is built from that folder only. The folder stays visible above the box, and every answer keeps a badge naming it, so a narrow answer is never mistaken for the whole truth. ALL DOCS widens it again.

Bấm một thư mục ở đó làm thêm việc thứ hai: câu trả lời sau đó chỉ dựng từ thư mục ấy. Thư mục đang chọn vẫn hiện trên ô nhập, và mỗi câu trả lời đều giữ một nhãn ghi tên nó, để câu trả lời hẹp không bị hiểu thành toàn bộ sự thật. ALL DOCS mở rộng lại.

Scope when the same word means two things. “Deposit” in support/ and “deposit” in booking/ are different rules, and an unscoped question can fuse them into one confident answer. Narrowing is also the fix for a thin answer in a large corpus: fewer candidate sections means the ones that reach the model are the relevant ones. It cannot invent coverage, though — a folder that does not answer the question says so, and that is a gap to file. Thu hẹp khi cùng một từ mang hai nghĩa. “Deposit” trong support/ và “deposit” trong booking/ là hai quy định khác nhau, và một câu hỏi không thu hẹp có thể trộn chúng thành một câu trả lời nghe rất chắc. Thu hẹp cũng là cách chữa câu trả lời mỏng khi corpus lớn: ít đoạn ứng viên hơn thì đoạn tới được model đúng là đoạn liên quan. Nhưng nó không tạo ra nội dung — thư mục không có câu trả lời sẽ nói vậy, và đó là một gap cần báo.
To get a document in: send whoever runs the server a .md or .txt file — PDF and DOCX must be converted first. Re-sending a corrected file updates it in place; there is no duplicate to clean up. Để thêm một tài liệu: gửi người chạy server một file .md hoặc .txt — PDF và DOCX phải chuyển trước. Gửi lại bản đã sửa thì nó cập nhật tại chỗ, không sinh bản trùng cần dọn.
Everyone who can reach the app can read everything in it. There are no per-document permissions. Anything you would not show the whole team should not be indexed. Ai vào được app là đọc được tất cả trong đó. Không có phân quyền theo từng tài liệu. Thứ gì bạn không muốn cả team thấy thì đừng index.

4 · Answer a gap so it stays answered

4 · Trả lời phần thiếu sao cho nó ở lại

This is the BA half of the BA tab. What you confirm becomes one retrievable section that the model is told to answer only from — so how it is written decides whether the next person finds it.

Đây là phần việc của BA trong tab BA. Thứ bạn confirm sẽ thành một đoạn truy xuất được, và model bị buộc chỉ trả lời từ đoạn đó — nên cách viết quyết định người sau có tìm thấy hay không.

When something's wrong

Khi có vấn đề

The four failures that actually happen, and what each one means.

Bốn lỗi thực sự hay xảy ra, và mỗi lỗi nghĩa là gì.

"Nothing is indexed yet" The app is fine, the index is empty — run make ingest DOCS=./docs. This message exists so an empty index can't be mistaken for a broken search. "Nothing is indexed yet" App bình thường, index đang trống — chạy make ingest DOCS=./docs. Thông báo này có để index trống không bị hiểu lầm thành tìm kiếm hỏng.
Ingest says "no embeddings endpoint" Your chat provider doesn't serve /embeddings — common for coding-agent gateways. Point embeddings elsewhere and keep chat where it is. Two ways: a local Ollama (free), or OpenAI for embeddings only. If the two are different vendors, EMBED_API_KEY is required — one key is not valid at both. Ingest báo "no embeddings endpoint" Provider chat của bạn không có /embeddings — rất thường gặp ở các gateway kiểu coding-agent. Trỏ embeddings sang chỗ khác và giữ chat ở nguyên đó. Hai cách: Ollama local (miễn phí), hoặc dùng OpenAI chỉ cho embeddings. Nếu là hai nhà cung cấp khác nhau thì phải set EMBED_API_KEY — một key không dùng được ở cả hai.
# free, nothing leaves the machine EMBED_BASE_URL=http://localhost:11434/v1 EMBED_MODEL=nomic-embed-text EMBED_DIM=768 # or OpenAI for embeddings only EMBED_BASE_URL=https://api.openai.com/v1 EMBED_API_KEY=sk-… EMBED_MODEL=text-embedding-3-small EMBED_DIM=1536
The dot in the header is red The browser can't reach /api/health: the server is down, or the tunnel is. The conversation on screen is kept in the browser, so nothing is lost. Đèn trên header màu đỏ Browser không tới được /api/health: server chết, hoặc tunnel chết. Hội thoại đang hiển thị được lưu trong browser nên không mất gì.
Answers arrive all at once, not word by word Something between you and the app is buffering the stream — usually a proxy. make live reports whether the provider itself streams incrementally, which tells you which side to look at. Câu trả lời hiện một lần chứ không từng chữ Có gì đó giữa bạn và app đang buffer stream — thường là proxy. make live cho biết provider có stream từng phần hay không, để bạn biết cần xem phía nào.
