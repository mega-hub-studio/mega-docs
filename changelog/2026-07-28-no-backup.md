# 2026-07-28 — There is no backup story, and that unblocks the source-of-truth inversion

Decided: **the backup requirement is dropped.** Not deferred, not pending — removed. The
reason given, and it is the one that matters: *knowledge base files are imported from the BA
WebUI, which controls the source of truth.* One controlled entry point is the property the
brief asks for; a second copy of the corpus is not what makes it true.

## What this settles

`2026-07-28-sot-decision.md` put two preconditions in front of inverting the source of truth,
in order:

1. a migration runner — **shipped** (`internal/db/migrate.go`)
2. an off-box DB backup — **dropped, here**

So nothing gates the inversion any more. `README.md`'s *Now vs vNext* moves that row from
⛔ **blocked** to 🟡 **next**: what remains is the work itself — stop writing files, let
`Upload` write straight to the Knowledge DB — with no precondition in front of it.

That is a real reversal of an earlier entry, which is why it is written down rather than
edited in. `sot-decision.md` and `vnext-collisions.md` still say backup comes first; they were
true on their date, and this file is how the world moving on gets recorded.

## What is actually protecting the corpus now

Worth stating plainly, because "no backup" sounds like an omission and this one is a choice:

- **One way in.** Every document arrives through `POST /api/documents` behind `BA_PASS`. There
  is no folder watch, no git sync, no second path — those were removed today too
  (`2026-07-28-drop-corpus-sync.md`).
- **Removal is soft.** `rag.Remove` moves the file to `docs/.trash/` inside the corpus rather
  than unlinking it, and `.trash/` needs no exclusion rule because a hidden path segment is
  already refused by `SafePath`. Recovery is one `mv`.
- **The database is still derived.** Deleting `knowledge.db` costs an index, not a document —
  `ingest` rebuilds it, confirmed answers included. That stays true until the inversion lands,
  and after it lands the migration runner is what carries the schema forward.

What is genuinely gone: if the corpus directory itself is lost, it is lost. Accepted.

## The other four gaps, resolved the same way: by deciding, not by building

Rule 20 says no knob nobody turns and no layer for a future that has not arrived. Applied to
what was left in *Now vs vNext*, it closes all of them:

- **`gate(role)` + `ADMIN_PASS` — not built, on purpose.** There is no admin-only *action* to
  gate: the brief's Admin does Users, Workspace, Billing, Logs, Analytics, Platform Settings,
  and none of those exist. Adding the variable now would be a knob with no job, and
  `TestEveryRouteAndKnobIsSpecified` would make us document it as if it did something. The two
  roles that exist are already expressed exactly once each: DEV reads (open), BA writes
  (`BA_PASS`). **Trigger: the first admin-only action.** It arrives with that, not before.
- **Related Documents · Suggested Actions — not built.** The brief lists the names and nothing
  else. "Suggested Actions" could be model-generated follow-ups, preset queries, or ticket
  shortcuts; guessing costs a field in `rag.Reply` and a shape in the renderer that the next
  reading of the brief would contradict. **Trigger: one sentence saying what they contain.**
- **Tags · Categories · Relations · Version — not built.** They are new *tables*, so they cost
  no re-ingest whenever they land, which is precisely why there is no hurry. Nothing in the UI
  asks for them yet. **Trigger: a BA screen that needs to filter by one.**
- **`ingest` CLI stays.** Settled already: an operator recovery tool, not a second way in. It
  reads 🟡 partial against "WebUI is the single entry point" and will keep reading that way,
  which is the honest state rather than an open question.

None of the four is a backlog item anybody should find and start. Each is a decision with a
named trigger, which is the difference between a decision log and a wish list.
