# 2026-07-30 — Five pairs of blocks touching at 0px, and a dismissed ticket with no way out

Both reported from a phone against the deployed instance, both measured at 390×844 in the
running product before and after.

## Rule 27, and the probe that is its enforcer

`.card` is not a flex container, and a design-system recipe spaces only *inside* itself. That
is the whole cause, and it had already been paid for three times — `.ticket`, `.drop` and
`.doc-form` each carried its own copy of `display: flex; flex-direction: column; gap: …` — so
the fourth card still had the bug and the fifth would have too. It is one declaration now,
`main .card`, and a card names only its own value.

Measured, before: **five** pairs of stacked blocks with nothing between them.

| pair | where |
|---|---|
| `.feedback → .callout` | the ticket badge against the actions row — `OPEN #2` sitting on the copy button's box, which is what was reported |
| `.prose → form.callout` | the clarify card against the answer it belongs to |
| `.field → .lib-rows` | the library's Find field against the document list |
| `.lib-rows → .doc-form` | that list against the form under it |
| `.field → .btn` | the unlock form's password field against its button |

Two more were left alone on purpose, and the reason is the part worth keeping: `.stat`'s number
against its label and `.result`'s title against its path are **two lines of one thing**, not two
blocks. 0px is the recipe there. Anything else left in the probe's output means the fix is not
finished.

The probe, because rule 27 is `prose only` and this is what replaces a browser rig (rule 21).
Paste into `pinchtab eval` with the app open at 390×844:

```js
(() => {
  const sel = el => el.tagName.toLowerCase() + (typeof el.className === 'string' && el.className
    ? '.' + el.className.trim().split(/\s+/).slice(0, 3).join('.') : '')
  const out = []
  for (const el of document.querySelectorAll('main *, main')) {
    const n = el.nextElementSibling
    if (!n) continue
    const a = el.getBoundingClientRect(), b = n.getBoundingClientRect()
    if (a.height < 2 || b.height < 2) continue
    if (b.top < a.bottom - 1) continue            // side by side, not stacked
    const gap = Math.round((b.top - a.bottom) * 10) / 10
    if (gap <= 3) out.push({ gap, pair: sel(el) + ' → ' + sel(n), parent: sel(el.parentElement) })
  }
  return JSON.stringify(out)
})()
```

Run it on `/#/ask` with a filed ticket **and** on `/#/ba` in both states — locked (the unlock
form is a card too, and it was one of the five) and unlocked with the document form open. After:
`[]` on ASK, and only the two library-internal pairs on BA.

Two containers are not cards and needed naming separately: a `<details>` (`.corpus > summary +
*`, because what it reveals opened flush against the label that revealed it) and the clarify
card, which is a `.callout` — a *text* recipe — used as a form. That one also gets
`align-items: start`, or the single ASK THIS button stretches to the card's width and reads as
the card's primary surface rather than as the answer to its question.

## `rejected` was the dead end `confirmed` used to be

Reported as: a DISMISSED ticket has no *Take this out of the knowledge base*, so it cannot be
cleared out of the system. Correct, and the cause is **UI-only** — everything under it already
worked:

- `db.DeleteTicket` is `DELETE FROM tickets WHERE id=?` with no status clause, so it has always
  applied to any state.
- `DELETE /api/tickets/{id}` is registered, and `lib/qa.js`'s `drop()` calls it.
- `composables/tickets.js` already owns `remove` and the two-press `armed` idiom.

What was missing is one branch: `TicketCard.vue`'s four-state cascade ended in a bare `v-else`
that rendered the reason callout and nothing else. That is the same shape as the defect the
four-verb work fixed for `confirmed` — a state a BA reaches by doing the work, with no edge out
of it — surviving in the state next to it.

DELETE sits inline on the card rather than behind the confirmed card's disclosure: a drawer
holding one button is ceremony, and the arming is what guards the press.

**No transition out of `rejected` was added, and that is deliberate.** `ticketByNorm` dedupes
only against `open` and `answered`, so a question dismissed in error is asked again and files a
*fresh* ticket — the recovery path exists without a new edge, and the store's own state diagram
stays four states with `delete` as the only way out. If a BA-side REOPEN is ever wanted it is
one word in `Draft`'s `WHERE … status IN (…)` plus a documented section, not a redesign.

## The citation digit was one device pixel high — upstream request #4

Reported with the devtools hack still attached: `<a class="cite" style="padding-top: 2px">1</a>`.

`.cite` already is `inline-flex; align-items: center; justify-content: center`, which is why it
could not fix itself — **flexbox centres the line box, and the line box is the font's em box,
not the ink.** Measured with the font's own metrics rather than by eye, at the chip's `.7em`
(9.8px NES Mono): em box ascent 9 / descent 3, a digit's ink ascent 7 / descent 0. So the box
being centred carries 2px of unused space above the glyph and 3px below, and the ink's optical
centre lands (3 − 2) / 2 = 0.5px high. `slack: {above: 3.86, below: 4.84}` in a 15.7px chip —
one device pixel at 2× DPR.

Fixed in the app with `padding-block-start: 0.1em`, which is that asymmetry rather than a nudge
that looked right: 1px at 9.8px, in `em` because the chip is sized in `em`. After:
`{above: 4.83, below: 4.84}`. The measurement script is in the scratchpad shape below — a
canvas `measureText` on the computed font is the only way to see ink rather than boxes:

```js
const cs = getComputedStyle(el), cv = document.createElement('canvas').getContext('2d')
cv.font = `${cs.fontWeight} ${cs.fontSize} ${cs.fontFamily}`
const m = cv.measureText(el.textContent)   // actualBoundingBox* is ink, fontBoundingBox* is the em box
```

**The upstream request** (fourth in AGENTS.md's table): put
`text-box-trim: trim-both; text-box-edge: cap alphabetic` on `.cite`. That trims the
half-leading to cap height and the alphabetic baseline, so `align-items: center` then centres
the ink exactly at every size and no padding constant is needed anywhere. Delete the local rule
on the release that ships it.

## A confirmed answer is named by the BA, not by its ticket number

`qa/ticket-2.md` tells a reader which ticket and nothing about the answer. It is a citation, so
it is read far more often than it is written — `qa/pricing-2026.md` is the same work and a
different document to meet.

One optional field, `name`, on the one action that writes a document. `rag.qaPath` is the whole
decision and its default is the part to keep straight:

| name | live doc | result |
|---|---|---|
| given | either | `qa/<name>.md` — folders allowed inside `qa/`, `.md` added, `qa/` not typed |
| empty | yes | **the path the ticket already has** |
| empty | no | `qa/ticket-N.md`, the id-derived fallback that used to be the only name |

That middle row is the load-bearing one: an empty name must never invent a path, or a client
that does not know about the field renames a document by omitting it. The server trims and
passes it through; `Confirm(ctx, id, answer, name)` carries it rather than a separate rename
verb, which would be a second way to change one fact.

**A different name on a published ticket is a rename, and it is honest rather than free.** The
old row is unpublished first — soft, so the words survive with a `deleted_at` — because two
documents holding one answer, one of them still retrievable under a name nothing points at, is
exactly the disagreement `unpublish` exists to prevent. The form says so *before* the press: the
hint prints the path the save will write, and adds "that is a rename — `<old>` stops being
retrieved" the moment the box stops matching the document.

Invariant 5 survives intact, which was the doubt worth resolving: the path is still one
identity: one live address per answer, changed by a deliberate action, never two.

Two bugs found by the tests written for it, both worth keeping in mind:

1. **`path.Join` cleans, so it defuses a `..` before the path check sees one.**
   `path.Join("qa", "../escape.md")` is `escape.md` — valid, outside `qa/`, and it would have
   published a BA-approved answer as an ordinary document. `qaPath` checks the *result* has the
   `qa/` prefix, which closes every spelling rather than the one that was tried.
2. **Seeding the name box with the file name loses the folder.** `fileName()` gives the leaf, so
   a document at `qa/business/pricing-2026.md` seeded the box with `pricing-2026.md`, the hint
   read "that is a rename" before the BA had typed anything, and saving a *correction* would
   have quietly moved the document up a folder. `qa.docName()` is the inverse of `qa.docPath()`
   and the box round-trips now — caught in the browser, not by a test, which is what verifying
   against the running product is for.

Verified end to end against a real instance: `{"name":"pricing-2026"}` → `qa/pricing-2026.md`;
re-confirm with `business/pricing-2026` → `qa/business/pricing-2026.md` with the old path gone
from the live corpus; `../escape` → **409** `"../escape.md" would leave the qa/ folder`.

The guide moved with it (rule 26): `ba.html` gains the naming paragraph and the rename warning
in its EDIT ANSWER row, and `dev.html`'s *"the document path is derived from the id"* — the
sentence that made a correction safe **because** nothing could move it — is retired in both
languages.
