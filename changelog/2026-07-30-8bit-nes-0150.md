# 2026-07-30 — 8bit-nes 0.14.0 → 0.15.0: all six requests landed, all six overrides deleted

The bump the override table was written for. Six requests went upstream in
`changelog/upstream-8bit-nes-0.14.0.md`; **0.15.0 ships all six**, so the "waiting on a release"
half of AGENTS.md is empty for the first time.

Every one was re-measured against the release's own bytes, never its changelog — that rule is
what caught the counter-example recorded below.

## What moved

| pin | from | to |
|---|---|---|
| `web/ui/package.json` + `package-lock.json` | `^0.14.0` | `^0.15.0` |
| `web/vendor.sha384` (5 entries) | `0.14.0` | `0.15.0`, two digests rewritten |
| `AGENTS.md` (4 quotes + the tables) | `0.14.0` | `0.15.0` |

On the bump **`all.min.css` and `elements.min.js` both changed digest; the three fonts came back
identical.** `make vendor` reported the two mismatches and refused to write anything until the
manifest was corrected, which is the whole point of pinning by content rather than by version.

## The six, and what the release does instead

| deleted from `styles.css` | 0.15.0 |
|---|---|
| `.prose a.cite` recoloured, un-underlined | the prose-link rule is `& a:not(.cite)` |
| `.prose a.cite { padding-block-start: 0.1em }` | `@supports (text-box-trim: trim-both)` trims the chip, **and switches it to `display: inline-block`** |
| `.empty .palette-list { max-block-size: none }` | the cap is scoped `:is(dialog, .modal) .palette-list` |
| `.drawer[open] { inset-inline-start: auto }` | the recipe sets it itself |
| `.prose nes-walkthrough { max-inline-size: none }` | the element is on `.prose`'s width opt-out list |
| `.diagram-zoom .zoom-stage { will-change: auto }` | no static hint at all — set on pointerdown/wheel, dropped ~200ms after the gesture |

Two of those are **better than what was asked for**, and both are worth reading:

- The chip needed `display: inline-block` as well. `text-box-trim` does nothing on an
  `inline-flex` — upstream measured it and said so in the comment. The local patch had papered
  over the same 1px with padding and never found out why the trim would not have been enough on
  its own.
- The `will-change` request was "drop it, or only hint it for a raster". The release does better:
  hint it **per gesture**. That keeps a vector sharp at rest *and* stops a compositing layer
  living for the page's whole life for every diagram on it — the thing MDN warns about, and
  something the requested fix would not have addressed.

## Verified after deleting them, at 390×844 against the running product

| override | measurement |
|---|---|
| chip ink | **−0.23px** off centre (was **+0.98px** on plain 0.14.0). Re-applying the old `0.1em` now measures **+0.73px** — the patch would have broken what the release fixed |
| chip colour | `rgb(51, 224, 224)` = `--cyan`, `text-decoration: none`, `display: inline-block` |
| walkthrough | library gives it `max-inline-size: none`; a `<p>` beside it still gets `646.126px` |
| in-page palette | `max-block-size: none`, `scrollHeight == clientHeight` — no nested scroller |
| drawer | rests flush **right** (`left 39, right 390` in a 390px viewport) |
| zoom at 3× | label sharp, no halo; `will-change` computes `auto` with no inline hint until a gesture |

**A measurement trap worth writing down.** The drawer first measured `left: 390` — entirely
off-screen — which reads exactly like the bug the deleted override fixed. It was not: headless
Chromium reports `document.visibilityState === "hidden"`, animations are throttled there, and the
`drawer-in` keyframes were frozen on their first frame. `getAnimations()` said
`drawer-in:running` while nothing moved. Removing the animation before measuring gives the
resting position, which is the thing under test.

The same shape caught the chip: the probe script from the last session added a half-leading term
that `text-box-trim` had just removed, and reported the digit **1.5px low** — a regression that
did not exist. A measurement that encodes an assumption about the old layout cannot be trusted
across the change that removed it. Both numbers above come from the range rect, which assumes
nothing.

## The counter-example, kept on purpose

`.prose nes-walkthrough` also carried `display: block`, and **that half had landed in 0.14.0** —
`components.css:460` blocks the element beside `nes-mermaid`. It sat in this repo for a release
because the comment said "reported upstream" and nobody went back to check. That is the argument
for AGENTS.md's re-measure rule in one line, and it is why the six rows above name what replaced
them rather than just disappearing.

## Three more stale claims the same re-read caught, in *this* repo's prose

The override table was the point of the bump, but re-reading 0.15.0's bytes against every
recorded claim turned up three sentences that were wrong. None of them broke anything, which is
exactly why they had survived.

- **`CLAUDE.md`'s `.steps` trap said `display: inline-flex`.** The list is `display: flex`;
  it is each `<li>` that is `inline-flex` (`components.css:1600`). The trap itself still holds —
  it is a stage bar, and `make check-ui` still fails on `main .steps > li` — only the property
  was misattributed.
- **`App.vue` said `<nes-zoom>` "does not do pinch".** It does, and it always did:
  `.zoom-view` sets `touch-action: none` *so that* the component owns the gesture, and it tracks
  two pointers itself with a `spread()` that anchors the scale on their midpoint. The repo
  contradicted itself here — `lib/diagram.js` has said "pinch, wheel and reset stay the
  element's" all along, and it was right. 0.15.0 only changed when `will-change` is raised.
- **`styles.css` said `.prose` caps an answer's image to the reading measure.** True in effect,
  wrong in mechanism, and the mechanism is what a reader needs — see below.

## The image measure, and a rule the wrapper was defeating

The library opts `img` out of `--prose-measure`, and states the principle in its own 0.15.0
notes: *"if the content is the width, it opts out."* But the opt-out is
`.prose > :is(… img …)` — a **direct child**. Markdown wraps every standalone image in a `<p>`,
and the paragraph carries the measure, so the picture was inheriting a 72ch cap through its
wrapper rather than from any rule about images.

Measured: a 1200px screenshot rendered at **646px**, half the card it sat in.

So `dressImages` now unwraps a paragraph holding nothing but an image, which hands the picture
back to the rule the library already documents. An image sharing a paragraph with text keeps its
wrapper — there it is part of a sentence and the measure is the right answer.

| image | parent | `max-inline-size` |
|---|---|---|
| beside text | `<p>` | `100%` — inside the measure, unchanged |
| alone in its paragraph | `.prose` | **`none`** — the library's own opt-out now applies |

Not verified: the pixel width of a *loaded* image. `dressImages` allows `https:` only, and this
sandbox has no network, so both probes were broken images. The constraint that governs the width
is the only thing the change touches, and that is what the table measures.

## Two things that did NOT change, and both matter

- **`<nes-code>` is byte-identical in behaviour.** Still an empty `NesCodeElement` interface,
  still only a `file` attribute, still one regex with a JS-only keyword list, still `_done`
  one-shot with no observer, still escaping only `& < >`. So the shiki upgrade layer
  (`lib/highlight.js`) is still doing work nothing upstream does, and the note asking for a
  `lang` attribute stays open.
- **`<nes-annotate>.open(index)` is still broken.** `index.d.ts` still declares one argument
  while the implementation is `open(i, pin)` and dereferences `pin.style` unconditionally.
  Hotspots over an evidence image still have to wait.

## Still ours, and re-measured as still needed

The other five overrides are this app using a recipe outside its context, so nothing upstream is
wrong and nothing landed: `.source-title` still underlines on hover, `.result` is still a control
(`cursor: pointer`, hover edge, `--pad-snug`), `.statusline` is still `inline-size: 100%` with
`.sl-end` pushed, `.palette-empty` is still centred, `::selection` is still a solid fill
(`base.css:137`). `.check` is also still `inline-flex` with no wrap — the reason the RECOMMENDED
badge became a star rather than getting a width patch.
