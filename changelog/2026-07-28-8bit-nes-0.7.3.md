# 2026-07-28 — 8bit-nes 0.7.3, and the workaround it retires

Upstream released the `<nes-toc>` fix this project reported, so both manifests move to
0.7.3 and `web/docsbase.html` gets to delete the thing it was doing instead.

## What was wrong, and where the fix now lives

Setting an observed attribute (`levels`, `label`, `target`) rebuilds the index: new rows,
and a new "current section" span. The component kept its active heading id across that
rebuild, and `_mark()` returns early on an id it believes is already marked — so the fresh
span was never filled, and stayed blank. These pages write **both** `label` and `levels` on
a language toggle, which is two rebuilds back to back, and the collapsed bar — which on a
phone *is* the index — went empty on every page after one tap on VI/EN.

The workaround was an ordering: write `label` first, so the `levels` rebuild came last and
was the one case where the component's first-heading id genuinely differed from the id it
still thought was active. Eleven lines of comment explaining a two-line sequence, which is
the shape of a workaround that wants to be a fix.

0.7.3 forgets the active id when it rebuilds. The ordering is no longer load-bearing and
the paragraph is gone; `setIf` stays, because skipping a write that changes nothing still
avoids two full index rebuilds on every toggle — but its comment now names the real reason
rather than a failure that no longer exists.

## Verified against the published bytes, not the changelog

A release has already once been tagged without the fix it claimed, so:

- The digests in `web/vendor.sha384` were computed from the npm tarball and then
  independently re-derived by `make vendor` (which fetches the registry tarball and refuses
  a mismatch). They also match the package's own `sri.json`. Only `elements.min.js` moved —
  `all.min.css` and the three woff2 faces are byte-identical to 0.7.2.
- The fix is *in* the minified bundle, not just the source: `elements.min.js` carries the
  `_active=""` reset ahead of the assignment.
- The behaviour was measured with the workaround removed: an iPhone 14 viewport, all four
  pages, EN → VI → EN, reading `.toc-now` after each toggle. Twelve measurements, twelve
  filled bars, the VI ones in Vietnamese (so the rebuild really did re-index the other
  language's headings), no console or network errors. `make check-ui` asserts the same
  thing on both viewports and passes.

The app was rebuilt too (`make ui` → `web/dist`, committed) and mounts clean on the new
bundle. The app renders no `<nes-toc>`, so the upstream change reaches it as a version
number and nothing else.

## Two documentation fixes that fell out of it

The README's "Frontend assets (CDN, pinned)" section still described the **pre-Vite** app:
"one embedded HTML file that pulls four things from jsDelivr", with `vue@3.5.40`,
`marked@18.0.7` and `dompurify@3.4.12` listed as CDN pins. They have been npm dependencies
bundled into `web/dist` since the migration, and `web/vendor.sha384` refuses to pin them —
so the section contradicted both the code and rule 7. It is now the two-manifest table it
should have become in the same commit as the migration.

`scripts/vendor.sh` was still telling the reader to "run with `ASSET_BASE=/vendor`", a knob
that migration deleted. The vendor tree exists for `rendocs -base /vendor` now, which is
also how `make check-ui` measures the pages, and the script says so.

Neither was reachable by a test, which is the honest reason both survived: rule 15 joins
*sections* to routes and env vars, and prose in a README is outside it.

## Deploying

`git pull && make build && sudo systemctl restart knowledge`. No Node on the host, no
schema change, no re-ingest. The startup line names the new version:

```
mega-docs on http://127.0.0.1:8080 (ui: vue 3.5.40 · 8bit-nes 0.7.3 · build 6c94e57f, auth: off, writes: BA into corpus)
```

The published guide picks up the new CDN pins on the next Pages deploy; the digests changed,
so a stale cached `elements.min.js` cannot be served under the new page — it would fail SRI
rather than run.
